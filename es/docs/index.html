Native Bundle quick start

Use the verified Native Bundle for your operating system. Its commands and state are separate from the legacy Wheel client.

  1. Verify the official delivery with the independent verifier and follow the included installation guide.
  2. For an existing installation, preserve its identity and state; check status before continuing.
  3. For a new Paid device, use register and the Native portal. Convert an existing Native Trial with paid on that same installation.
  4. Confirm the valid signed Lease and test Gateway → Core → Protected Handler before opening production traffic.

Existing Wheel installation guide

Los comandos Wheel odre-pqc-commercial activate/deactivate no son comandos Native. No utilices el estado Wheel para activar o trasladar Native. El cambio de dispositivo o servidor requiere revisión y aprobación de soporte. El launcher publicado no permite el traslado autónomo. Un registro nuevo no transfiere una Unit. Elige expresamente transferir una Unit existente o asignar otra disponible. No repitas Trial como sustituto de un traslado.

  1. Verifica e instala el bundle oficial; comprueba las dependencias.
  2. Solo en instalaciones nuevas: odre-pqc init.
  3. Ejecuta odre-pqc doctor.
  4. Ejecuta odre-pqc verify (autoprueba independiente de Core).
  5. En main.py, registra Core con install(app) y después conecta Gateway y Commercial gate; configura identity, trust y rutas protegidas.
  6. Completa la activación Trial o, para una licencia de pago, odre-pqc-commercial activate y la aprobación web.
  7. Consulta odre-pqc-commercial status; para activación de pago confirma ACTIVE, LEASE_VALID, integrity PASS y la asignación de Unit.
  8. Inicia el servidor del cliente y Gateway private Core.
  9. Ejecuta odre-pqc status para el Core en ejecución previsto.
  10. Prueba la ruta real Gateway → Core → Protected Handler y fail-closed; distingue esta prueba de las autopruebas de Core.
  11. Abre el tráfico de Production únicamente tras superar todos los Gates aplicables.
Verifica la firma del Release Manifest → SHA-256 del artifact → instala solo después de PASS. El hash público del Core Wheel v0.2.9 es una referencia de Core, no el hash del bundle final Commercial + Gateway + Core.

Verification & known limitation

Instalación

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

Antes de instalar, verifica la firma del Release Manifest y el SHA-256 del bundle oficial; después comprueba las dependencias. Utiliza el bundle Commercial + Gateway + Core suministrado y su guía de instalación.

  1. Confirme Windows Server 2022 AMD64 o Ubuntu 24.04 LTS AMD64 y CPython 3.12.
  2. Antes de instalar, verifica la firma del Release Manifest y el SHA-256 del bundle oficial; después comprueba las dependencias. Utiliza el bundle Commercial + Gateway + Core suministrado y su guía de instalación.
  3. Verifica la firma del Release Manifest → SHA-256 del artifact → instala solo después de PASS. El hash público del Core Wheel v0.2.9 es una referencia de Core, no el hash del bundle final Commercial + Gateway + Core.
  4. Ejecuta odre-pqc init una sola vez y únicamente en una instalación nueva. Conserva la configuración, las claves y el estado existentes al actualizar o reinstalar. Antes de iniciar el servidor, ejecuta odre-pqc doctor y después odre-pqc verify. Verify es una autoprueba independiente de Core, no una prueba de tu integración con Gateway.
  5. Importa ODRE PQC, registra el límite Core con install(app) y después conecta Gateway y Commercial gate en main.py. Configura identity, claves, trust, rutas protegidas y startup/shutdown de Gateway. Registrar Core no completa por sí solo la integración. Completa la activación de Trial o de licencia de pago que corresponda y comprueba Commercial status. Inicia el servidor y private Core, consulta el estado de Core en ejecución y verifica Gateway → Core → Handler con una prueba de integración antes de abrir el tráfico.

Integración de Production

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

El punto de entrada confirmado para registrar Core es intencionadamente pequeño:

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)
Este código solo registra el límite de Core. El uso en Production requiere además Gateway y Commercial gate del bundle del cliente, junto con la configuración de identity, claves, trust, rutas protegidas, inicio y cierre.

odre-pqc verify es una autoprueba independiente de Core. No demuestra la ruta activa Gateway → Core → Protected Handler; ejecute la prueba de humo específica de la versión antes de abrir tráfico protegido.

Entrega de licencia

En una compra normal con Paddle, el correo del pago se vuelve a verificar mediante el proceso firmado y se usa para entregar la licencia. La página de retorno del navegador no es prueba de pago por sí sola.

License ID y License Key del correo de entrega pueden verificarse con el servidor en la página segura de activación. La vinculación del dispositivo y la emisión de Offline Lease se completan en ODRE PQC instalado.

Operación y actualizaciones

Status

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc status consulta evidencia autenticada del runtime de Core en ejecución, no un archivo de resultados de verify. Ejecútalo después del arranque. Un Core status correcto no verifica por sí solo Gateway private Core ni Gateway → Core → Handler; se necesita una prueba de integración separada.

Verify

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc verify ejecuta autopruebas criptográficas independientes de Core con claves y DB temporales, incluidas ML-KEM-768 y ML-DSA-65. Se ejecuta durante la instalación; no demuestra la integración FastAPI/Gateway del cliente ni debe repetirse con ese fin.

Operaciones

Un cierre normal detiene nuevas admisiones protegidas, completa dentro de límites el trabajo en curso, elimina sesiones y leases, cierra recursos nativos, libera bloqueos y registra el estado detenido. La recuperación tras un fallo vuelve a comprobar propiedad, bloqueos obsoletos, sesiones y runtime parcialmente inicializado antes de Ready.

Actualización

Las actualizaciones verificadas usan la ruta compatible. Si no pueden completarse con seguridad, la versión activa no cambia.

Solución de problemas

Doctor

Diagnostica sistema operativo, arquitectura, runtime de Python, permisos de archivos y directorios padre, hashes, símbolos, providers, dependencias y acceso al estado local. Una condición sin resolver bloquea el tráfico protegido.

Solución de problemas

  • Hash distinto: detenga la instalación y vuelva a obtener el artefacto por el canal oficial.
  • SO, arquitectura o versión de Python no compatibles: no presente el entorno como verificado; contacte con soporte técnico antes del despliegue.
  • Fallo de doctor o verify: mantenga deshabilitado el tráfico protegido hasta resolver la condición indicada.
  • Falta el correo de licencia: no compre de nuevo; use recuperación o soporte de licencias.
  • Instrucciones operativas no públicas: use la guía del cliente entregada con la versión.
