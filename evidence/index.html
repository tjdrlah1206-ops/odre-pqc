Evidence

What we tested, and what happened.

Marketing claims are not evidence. Every result below states the condition it was tested under.

All results below reflect the tested condition described, not a guarantee under every possible real-world attack or failure.

Security Enforcement

fail-closed

Unverified request sent to a protected route

RESULTIn this test, the protected handler did not execute.

An unverified request never reaches your application code — enforcement happens at the boundary, not inside your handler logic.

replay

Valid request resent to the same protected route

RESULTIn this test, the resent request was rejected by the boundary.

Replay defense doesn't depend on your application implementing its own idempotency checks.

sequence

Requests sent out of expected sequence within a session

RESULTIn this test, out-of-sequence requests were rejected.

Session integrity is enforced independently of request timing or network reordering.

binding

Request or response altered after being bound to its session

RESULTIn this test, the binding check failed and the request/response was rejected.

Confirms a request and its response can't be substituted across sessions under the tested conditions.

Integrity

update signature

Update package signature checked before staging

RESULTIn this test, unsigned or invalid packages were rejected before reaching staging.

Every update that reaches your servers has been verified before it's ever activated.

runtime

Runtime artifact checked against signed manifest

RESULTIn this test, a tampered artifact was detected before execution.

This covers the ODRE PQC runtime's own artifacts — not the integrity of the underlying OS, kernel, or hypervisor.

Update Safety

atomic switch

Staged update completes self-test and proceeds to activation

RESULTIn this test, traffic was drained, the switch to the new version was atomic, and health was verified afterward.

There's no observed window where traffic is served by a half-updated, unverified state.

rollback

Health verification fails after an update is activated

RESULTIn this test, the runtime rolled back automatically to its own last known-good version and configuration.

A bad update doesn't require a human to notice and intervene before the ODRE PQC runtime is restored. This does not extend to your application's data or state.

Recovery

process kill

ODRE PQC process terminated unexpectedly

RESULTIn this test, the ODRE PQC process recovered automatically to its own last known-good state.

A crash of the ODRE PQC process doesn't require manual restart or manual verification before it's safe to serve traffic again.

reboot

Host rebooted

RESULTIn this test, the security boundary resumed enforcement after the reboot without manual reconfiguration of the product.

Recovery from a reboot is part of the product itself, not a runbook your team maintains separately.

Platform Verification

Installation and operation were verified on: Windows Server 2022 AMD64; Ubuntu 22.04 AMD64; Ubuntu 24.04 AMD64; Debian 12 AMD64; Rocky Linux 9 AMD64; AlmaLinux 9 AMD64. Windows Server 2019, Windows Server 2025, RHEL 9, and ARM64 are not currently listed as officially supported.
