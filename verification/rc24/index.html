Windows Server 2022 AMD64 is one of six verified operating systems. This result is separate from Public Authenticode.

Official release verification model

Release pin → CMS signing authority → signed CRL → independent verifier → signed outer inventory and authenticated Product envelope → manifest/SHA. Any failed check stops installation.

Independent verification procedure

  1. Obtain Release 64 hashes and pins through an independently authenticated official channel.
  2. Verify the Customer Delivery filename and SHA-256 before running product code.
  3. Verify detached CMS and signed CRL with the pinned root and signer. Do not import the private root into Windows Trusted Root.
  4. Verify signed OUTER_INVENTORY, Product envelope, Product SHA-256, inner Ed25519 manifests, runtime inventory and sealed Core identity.
  5. Install only after every gate passes; preserve identity, License, Unit, Lease and Gateway state.

Windows Public Authenticode context

Public Authenticode is not the release trust authority and must not be confused with Windows Server 2022 support or the 6/6 validation result. Do not weaken Windows security controls.

Evidence boundary and future publication binding

Release 64 CMS binds the signed outer file inventory and inner Product envelope. g270 SHA256SUMS records the final Customer Delivery ZIP hash, but Release 64 has no Signed Publication Manifest binding the final outer ZIP container bytes. Do not claim otherwise. Starting with a future new Release, the approved design will bind filename, size, SHA-256, Release and Closure under the same signing authority. Release 64 evidence is not rewritten retroactively. The 6/6 result is product evidence, not third-party certification.
