Known Limitation — Authenticode
Windows Public Authenticode trust is not provided for RC24. Windows may show an unknown publisher or an untrusted chain; enterprise execution policies may block it. The product CMS verification is separate and does not override Windows policy. Do not disable SmartScreen, application control, revocation checks or security software to continue.

Required verification order

  1. Authenticate the release record; compare the customer ZIP, verifier ZIP and policy hashes. Unpack only the hash-verified external verifier into a new directory. Never run a verifier taken solely from an unverified product archive.
  2. Use an independently trusted Python 3.12 with cryptography and an approved Windows PowerShell executable. Generate the host-local verifier config from the pinned policy and record its returned trust_sha256.
  3. Verify detached CMS using the pinned root and CMS signer, certificate validity and EKU, then the signed CRL issuer, signature, validity interval and signer revocation status. The verifier reads public certificates and CRL locally; it does not register an OS Trusted Root.
  4. Verify the authenticated envelope and expected product ZIP hash, release generation, archive paths/CRC/coverage, each file hash, inner Ed25519 manifest, encrypted Core identity and signed runtime inventory.
  5. Only after verification succeeds may the existing verifier publish the new installation atomically. The supported launcher checks the Native executable before launch; Native checks runtime, authority and Lease contracts. Any failed check stops the corresponding protected path. Do not extract manually or run a loose EXE to bypass the verifier.

Bundled signed CRL expires at 2026-09-29 11:08:49 UTC. This is a bounded offline revocation snapshot, not a promise of immediate revocation updates. Obtain an authenticated current CRL before expiry; stale or invalid CRL must stop installation. RC24 Authenticode separately references a local-file CRL; this page does not claim that Windows public revocation validation succeeds.

Windows verification commands

Templates below require an authenticated RC24 delivery, a trusted Python 3.12/cryptography installation, an approved PowerShell hash and operator SID. Measuring an arbitrary executable does not approve it. Run from the verified external kit directory. No certificate-store import or ExecutionPolicy bypass is used.

$verifierZip = '.\ODRE_PQC_EXTERNAL_VERIFIER_0.3.0.zip'
$expectedVerifier = '182ED150DC01064ADDD1AEBEEA8BE9F9CCC7BAA7E577E9144F11B52DF18D7C80'
if ((Get-FileHash -LiteralPath $verifierZip -Algorithm SHA256).Hash -cne $expectedVerifier) {
    throw 'VERIFIER_ZIP_HASH_MISMATCH'
}
# Only after authenticating the expected pin; destination must be new.
if (Test-Path -LiteralPath '.\rc24-verifier') { throw 'DESTINATION_EXISTS' }
Expand-Archive -LiteralPath $verifierZip -DestinationPath '.\rc24-verifier'
Set-Location -LiteralPath '.\rc24-verifier' 
$delivery = '<RC24_DELIVERY_DIRECTORY>\ODRE_PQC_PRODUCTION_0.3.0_CUSTOMER_DELIVERY.zip'
$expectedDelivery = '3A14BE4D12241CB2C675626958E7F6B6E4A86F2A77D53D92D14526B3277B5A0B'
if ((Get-FileHash -LiteralPath $delivery -Algorithm SHA256).Hash -cne $expectedDelivery) {
    throw 'RC24_DELIVERY_HASH_MISMATCH'
}
# Unpack this authenticated outer delivery only; do not extract the inner product ZIP.
if (Test-Path -LiteralPath '.\rc24-delivery') { throw 'DESTINATION_EXISTS' }
Expand-Archive -LiteralPath $delivery -DestinationPath '.\rc24-delivery' 
$python = '<TRUSTED_PYTHON_3_12_ABSOLUTE_PATH>'
& $python -B .\prepare_customer_verifier_config.py `
  --policy .\verifier-policy.json `
  --policy-sha256 '4BADE8AF01F2BC1F899F2B226604C690C27D6A7AE0A19C62A879AFCF90622FF5' `
  --platform windows `
  --cms-tool '<APPROVED_POWERSHELL_EXE_ABSOLUTE_PATH>' `
  --cms-tool-sha256 '<INDEPENDENTLY_APPROVED_POWERSHELL_SHA256>' `
  --operator-sid '<APPROVED_OPERATOR_SID>' `
  --output .\local-trust.json
if ($LASTEXITCODE -ne 0) { throw 'VERIFIER_CONFIGURATION_FAILED' }
& $python -B .\trusted_preinstall.py `
  --bundle '<RC24_PRODUCT_DIRECTORY>\ODRE_PQC_PRODUCTION_0.3.0.zip' `
  --envelope '<RC24_PRODUCT_DIRECTORY>\bundle-envelope.json' `
  --cms '<RC24_PRODUCT_DIRECTORY>\envelope.p7s' `
  --trust .\local-trust.json `
  --trust-sha256 '<RETURNED_TRUST_SHA256>' `
  --expected-bundle-sha256 '2A49C6F2FE0BA0702E615B6A55434E52F7826340B636FAB9F6FA1062ED389DC3'
if ($LASTEXITCODE -ne 0) { throw 'PREINSTALL_FAILED' }

After PREINSTALL=PASS, follow the signed RC24 Native guide and its existing identity-preserving upgrade procedure.
