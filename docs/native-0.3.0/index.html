ODRE PQC Production 0.3.0 - Native installation and integration guide

The product version is 0.3.0; the Native component is 0.3.0-rc.24. Before customer operation, match the installation archive to the final ZIP SHA-256 in the release approval report and confirm that all required gates have passed.

ODRE PQC registers and activates devices using the installation identity and device keys, without customer sign-up or login. An operating-system execution account below controls file permissions and process execution; it is not an ODRE customer account.

Protection boundary

External Client → HTTPS/TLS → customer Nginx → Native HTTPS Gateway → ODRE v3 / Native Lease gate → in-memory Private Core → customer Protected Handler. A client PQC SDK is unnecessary when the supported API contract matches. This is not client-to-handler E2E PQC. Keep customer authentication, authorization and input validation. Never proxy a protected route directly to the backend. This product does not replace a WAF, HSM or OS security.

Verification before installation

Use the verifier, trust pin and final ZIP SHA-256 received through an independently trusted channel. Do not execute bundled Python or Native before verifying the outer CMS, inner Ed25519 signatures, file inventory and runtime. Do not bypass failure by extracting manually. Use verifier --install-new only for a new empty destination. Follow the upgrade contract for an existing installation.

Public Windows Authenticode trust is not provided. Use an independently obtained pin to verify the independent verifier → CMS → signed CRL → manifest/SHA chain. Never automatically register the Private Root in Windows Trusted Root or ignore verification failures.

Supported environments and first installation

Targets are Windows Server 2022 AMD64 and Ubuntu 24.04 AMD64. The Ubuntu launcher needs Python 3.12; keep the runtime root-owned and run under a dedicated non-root operating-system account. Preserve the included Windows runtime. First installation: verify/install → identity once → trial → status → configure Gateway/backend → run → verify protected requests and restart → open traffic. Core initialization, doctor and verify run inside the authenticated in-memory Native path. Do not invoke nonexistent init/doctor/verify launcher actions or install a plaintext Core Wheel.

14-Day Free Trial and Paid conversion

Free download; no email required; downloading does not start Trial; 14 days from first successful activation; one Device, one Trial; downloading or reinstalling cannot reset it; protected routes fail closed after expiry; purchase converts to Paid without reinstalling. Keep the same operating-system execution account, state-directory and identity. The paid action reads License ID in a normal prompt and License Key in a hidden prompt, then passes them through stdin. Native Paid is not the Wheel web Device Code approval flow. Check status and protected requests after conversion; restart the same run when necessary.

Using the commands

Run from the installed folder for the selected OS. Replace <...> with approved absolute paths or public SHA-256 values. Use the same state-directory for every action. Never place secret values on the command line. A separate business venv contains customer application dependencies only.

Windows Server 2022

$state = 'C:\ProgramData\ODRE\native-commercial'
$trust = '<APPROVED_TRUST_JSON_ABSOLUTE_PATH>'
$trustPin = '<INDEPENDENT_TRUST_SHA256>'
& .\runtime\python.exe .\odre-native.py identity `
  --state-directory $state
& .\runtime\python.exe .\odre-native.py trial `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin
& .\runtime\python.exe .\odre-native.py status `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin
& .\runtime\python.exe .\odre-native.py run `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin `
  --gateway-config '<GATEWAY_JSON_ABSOLUTE_PATH>' `
  --gateway-pin '<GATEWAY_JSON_SHA256>' `
  --backend-script '<BACKEND_ENTRYPOINT_ABSOLUTE_PATH>' `
  --backend-python '<BUSINESS_VENV_PYTHON_ABSOLUTE_PATH>'

Gateway and business processes

The configuration accepts only the exact keys in the schema below. Bind to 127.0.0.1 with port 1024–65535, distinct from the Native port and ten consecutive backend ports. Specify 1–128 method/path entries. After /secure/, only letters, digits, underscores, hyphens and slashes are allowed; no duplicate/trailing slash, wildcard or path parameter. GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD may be listed. POST requires an application/json object and rejects duplicate JSON keys. Do not assume array, multipart, raw upload or large-payload support. max_pending is 1–16, not a throughput promise. Maintain CORS and existing authentication separately.

The backend must bind to 127.0.0.1 at the ODRE_R1_BACKEND_PORT environment value. Native manages workers on ten consecutive ports. Do not run shared DB migrations or a singleton scheduler in every worker. Supply Gateway TLS certificates and encrypted PEM private keys through approved absolute paths with restricted permissions. Inject the password through the ODRE_GATEWAY_TLS_KEY_PASSWORD secret environment variable; Native removes it from the business backend environment. Pin the exact reviewed Gateway JSON bytes using --gateway-pin.

{
  "schema": "odre-native-gateway-host/v1",
  "listen_host": "127.0.0.1",
  "listen_port": 29443,
  "routes": [
    {
      "method": "POST",
      "path": "/secure/echo"
    }
  ],
  "tls_certificate": "<ABSOLUTE_CERTIFICATE_PATH>",
  "tls_private_key": "<ABSOLUTE_ENCRYPTED_PEM_PATH>",
  "max_pending": 16
}

State, upgrades and recovery

Preserve Gateway identity at state-directory/r1-broker-home/gateway-identity. Retain Windows DPAPI/restricted ACL and Ubuntu operating-system service-account-owned 0600 encrypted state. Local Linux encryption is not an HSM against administrator compromise. Preserve identity, device.json, original Trial times, Paid entitlement, Unit ownership and Lease generation. Do not initialize identity or rerun init on reinstall/upgrade, or copy state to another device. Verify the new Bundle in a separate directory and apply only authority-approved source/target upgrade contracts. Never add arbitrary allowlist entries or downgrade.

After prepare and before authority commit, abort restores the last valid state. If the response is lost after authority commit, recover the same authenticated commit by rolling forward. Do not restore old files after commit. Use authenticated recovery instead of deleting corrupted state to register again. Stale artifacts and tampered migration metadata must be rejected.

Expiry, operational checks and scope

A valid Lease/status alone does not prove business integration. Match successful protected responses to one Handler execution using distinct request IDs. After Lease expiry, Core rejects with 403; when Native stops the broker, Nginx may return 502. Do not convert failure to 200 or automatically resend business requests. Preserve public-route policy. Isolated Nginx HTTPS → Gateway → Core → Handler, Trial/Paid, restart, natural Lease expiry and RC2.5 upgrades were tested on both OSes. Consult the final report for final-ZIP clean-room and complete load gates.

Windows Nginx named-pipe password delivery was not verified. The isolated test used an ACL-restricted temporary test password file deleted immediately after Nginx started; no production key was used. Protect production secret delivery for the customer environment. Functional or fuzz counts do not establish maximum RPS, unlimited concurrency, SLA, absence of long-term memory leaks or 128KiB/1MiB payload support.

New Paid registration and existing Unit transfer

For a new Paid device without Trial, create identity once and run register. Use paid only to convert an existing Trial on the same device, preserving its identity and Trial history. Trial device transfer is unsupported.

Run register on the new server and enter its Device Code at https://pqc.odreai.com/payment/register/?flow=native . Verify License ID and License Key there, then explicitly choose a new Unit or an existing Unit transfer. No customer account or login is required. Never place License Key in command arguments, support messages or the source request file.

For transfer, select the existing installation and normal replacement or inaccessible source. Registration alone never transfers a Unit. Normal replacement requires an approved source version supporting transfer-release; upgrade older installations through the authorized identity-preserving contract first.

Normal replacement: stop new incoming business traffic while keeping the source Native running. Download the source transfer request JSON from the page, then run transfer-release below on the source. Native closes admission, drains in-flight requests, persists protected intent and submits signed device proof. Do not restart the retired source after completion.

Broken-device replacement needs support approval. If Native stops during normal drain, select the inaccessible-source confirmation and recovery action in the same web operation. The new Native signs separate recovery consent and support approves it. Do not change the selected Unit or assume a successful drain. Both paths wait for every previous Offline Lease to expire before issuing new protected execution authority.

Resume register with the same state-directory. After server commit, lost responses or disk errors recover the same operation result, verify signatures and new-device binding, then store atomically. Do not allocate another Unit, register another Trial, restore old state or copy private keys, DPAPI or Gateway identity between devices. The destination uses its own keys and Gateway identity.

LICENSE_UNIT_LIMIT means transfer or additional capacity is required. SUPPORT_PENDING awaits approval; WAITING_OLD_LEASE awaits expiry. COMMITTED means server commit, while APPLIED confirms local Native storage. Neither proves business integration. Verify status, Gateway→Core→Handler requests and restart before opening traffic.
