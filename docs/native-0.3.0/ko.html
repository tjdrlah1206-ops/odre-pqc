ODRE PQC Production 0.3.0 - Native 설치 및 통합 가이드

제품 버전은 0.3.0이며 Native 구성요소는 0.3.0-rc.24입니다. 고객 운영 전 배포 승인 보고서의 최종 ZIP SHA-256과 설치할 파일을 대조하고 모든 필수 Gate가 통과했는지 확인합니다.

ODRE PQC는 고객 회원가입·로그인 없이 설치 identity와 장치 키를 기반으로 장치를 등록·활성화합니다. 아래 실행계정은 파일 권한과 프로세스 실행에 사용하는 운영체제 계정을 뜻하며 ODRE 고객 계정이 아닙니다.

보호 경계

외부 Client → HTTPS/TLS → 고객 Nginx → Native HTTPS Gateway → ODRE v3 / Native Lease gate → 메모리 내 Private Core → 고객 Protected Handler. 지원 API 계약이 일치하면 Client에 PQC SDK가 필요하지 않습니다. Client부터의 E2E PQC가 아닙니다. 기존 사용자 인증·권한·입력 검증은 고객 앱에 유지합니다. Protected 경로를 backend로 직접 proxy하지 않습니다. WAF·HSM·OS 보안을 대체하지 않습니다.

설치 전 검증

별도 신뢰 경로로 받은 verifier, trust pin, 최종 ZIP SHA-256을 사용합니다. 외부 CMS, 내부 Ed25519 서명, 파일 inventory 및 runtime 검증이 끝나기 전에는 Bundle의 Python·Native를 실행하지 않습니다. 검증 실패 시 수동 압축 해제로 우회하지 않습니다. verifier의 --install-new는 비어 있는 새 경로에만 사용합니다. 기존 설치는 아래 업데이트 계약을 따릅니다.

Windows 공인 Authenticode 신뢰는 제공되지 않습니다. 별도 신뢰 경로의 pin으로 독립 verifier → CMS → signed CRL → manifest/SHA를 검증합니다. 고객 Windows Trusted Root에 Private Root를 자동 등록하지 않으며 검증 실패를 무시하지 않습니다.

지원 환경과 신규 설치 순서

Windows Server 2022 AMD64 및 Ubuntu 24.04 AMD64만 대상입니다. Ubuntu launcher에는 Python 3.12가 필요하며 runtime은 root 소유, 실행은 전용 비-root 운영체제 실행계정으로 합니다. Windows는 포함된 runtime을 유지합니다. 최초 설치: 검증·설치 → identity 1회 → trial → status → Gateway/backend 설정 → run → 보호 요청 및 재시작 검증 → 트래픽 개방. Native의 인증된 메모리 경로에서 Core 초기화·doctor·verify가 수행됩니다. 이 launcher의 action에 없는 init/doctor/verify를 별도 실행하거나 평문 Core Wheel을 설치하지 않습니다.

다운로드 무료 · 이메일 불필요 · 다운로드 시 Trial 미시작 · 최초 정상 활성화부터 14일 · 1 Device 1 Trial · 재다운로드/재설치로 초기화 불가 · Trial 만료 후 Protected Route fail-closed · 구매 시 재설치 없이 Paid 전환. 같은 운영체제 실행계정·state-directory·identity를 유지합니다. paid action은 License ID를 일반 프롬프트, License Key를 숨김 프롬프트로 받아 stdin으로 전달합니다. Native Paid를 Wheel의 웹 Device Code 승인 흐름과 혼동하지 않습니다. 전환 후 status 및 보호 요청을 확인하고 필요 시 같은 run을 재시작합니다.

명령 사용

설치된 해당 OS 폴더에서 실행합니다. <...>를 승인된 절대경로 또는 공개 SHA-256으로 바꿉니다. 모든 명령에서 같은 state-directory를 사용합니다. 비밀값을 명령행에 넣지 않습니다. 별도 업무 venv는 고객 앱 의존성만 담습니다.

Windows Server 2022

$state = 'C:\ProgramData\ODRE\native-commercial'
$trust = '<APPROVED_TRUST_JSON_ABSOLUTE_PATH>'
$trustPin = '<INDEPENDENT_TRUST_SHA256>'
& .\runtime\python.exe .\odre-native.py identity `
  --state-directory $state
& .\runtime\python.exe .\odre-native.py trial `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin
& .\runtime\python.exe .\odre-native.py status `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin
& .\runtime\python.exe .\odre-native.py run `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin `
  --gateway-config '<GATEWAY_JSON_ABSOLUTE_PATH>' `
  --gateway-pin '<GATEWAY_JSON_SHA256>' `
  --backend-script '<BACKEND_ENTRYPOINT_ABSOLUTE_PATH>' `
  --backend-python '<BUSINESS_VENV_PYTHON_ABSOLUTE_PATH>'

Ubuntu 24.04

state="$HOME/.local/state/odre-pqc/native-commercial"
trust='<APPROVED_TRUST_JSON_ABSOLUTE_PATH>'

python3.12 ./odre-native-ubuntu.py identity \

python3.12 ./odre-native-ubuntu.py status \
  --state-directory "$state" \
  --trust-config "$trust" --trust-pin "$trust_pin"
python3.12 ./odre-native-ubuntu.py run \
  --state-directory "$state" \
  --trust-config "$trust" --trust-pin "$trust_pin" \

  --gateway-pin '<GATEWAY_JSON_SHA256>' \

  --backend-python '<BUSINESS_VENV_PYTHON_ABSOLUTE_PATH>' \
  --core-startup-seconds 120

Gateway 및 업무 프로세스

Gateway 설정은 아래 스키마의 정확한 키만 허용합니다. 127.0.0.1, port 1024~65535를 사용하며 Native port 및 backend의 연속 10개 port와 겹치지 않게 합니다. routes는 1~128개 명시적 method/path입니다. /secure/ 뒤 영문·숫자·underscore·hyphen·slash만 허용하며 중복/끝 slash, wildcard, path parameter는 허용하지 않습니다. GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD를 명시할 수 있습니다. POST는 application/json의 JSON object이며 중복 JSON key를 거부합니다. array·multipart·raw upload 및 대용량 지원을 추측하지 않습니다. max_pending은 1~16이며 처리량 보장이 아닙니다. CORS와 기존 인증 계약은 고객이 유지합니다.

backend는 ODRE_R1_BACKEND_PORT 환경변수의 포트에 127.0.0.1로 bind해야 합니다. Native는 연속 10개 포트에 backend worker를 관리합니다. 공유 DB migration·scheduler를 worker마다 중복 실행하지 않습니다. Gateway TLS 인증서·암호화 PEM private key는 승인된 절대경로와 제한된 권한으로 제공합니다. 비밀번호는 ODRE_GATEWAY_TLS_KEY_PASSWORD secret 환경변수로 주입합니다. 이 변수는 업무 backend에 전달되지 않습니다. 검토한 Gateway JSON 원본 바이트 SHA-256을 --gateway-pin으로 고정합니다.

{
  "schema": "odre-native-gateway-host/v1",
  "listen_host": "127.0.0.1",
  "listen_port": 29443,
  "routes": [
    {
      "method": "POST",
      "path": "/secure/echo"
    }
  ],
  "tls_certificate": "<ABSOLUTE_CERTIFICATE_PATH>",
  "tls_private_key": "<ABSOLUTE_ENCRYPTED_PEM_PATH>",
  "max_pending": 16
}

상태 보관·업데이트·복구

Gateway identity는 state-directory/r1-broker-home/gateway-identity에 보존됩니다. Windows DPAPI 및 제한 ACL, Ubuntu 운영체제 서비스 계정 소유 0600 암호화 state를 유지합니다. Linux 로컬 암호화는 관리자 탈취를 막는 HSM이 아닙니다. identity·device.json·Trial 최초 시각·Paid entitlement·Unit·Lease generation을 보존하며 재설치/업데이트 때 init이나 identity 초기화를 하지 않습니다. state를 다른 장치로 복사하지 않습니다. 새 Bundle은 별도 경로에서 검증하고 실제 authority가 승인한 source/target upgrade 계약만 적용합니다. 임의 allowlist 추가나 downgrade는 금지합니다.

prepare 후 authority commit 전에는 abort로 마지막 정상 상태를 복구합니다. authority commit 이후 응답이 유실되면 인증된 동일 commit 복구로 roll-forward합니다. commit 완료 뒤 과거 파일 복사로 되돌리지 않습니다. 손상된 state는 지워서 재등록하지 말고 인증된 복구를 사용합니다. 오래된 artifact와 변조된 migration metadata는 거부되어야 합니다.

만료·운영 확인 및 검증 범위

유효 Lease와 status만으로 업무 통합 완료를 판정하지 않습니다. 고유 요청 ID로 보호 응답과 Handler 실행을 1:1 확인합니다. Lease 만료 시 Core는 403으로 차단하며 Native가 broker를 종료하면 Nginx는 502 등을 반환할 수 있습니다. 실패를 200으로 바꾸거나 업무 요청을 자동 재전송하지 않습니다. 공개 경로 정책은 유지합니다. 양 OS의 격리 Nginx HTTPS → Gateway → Core → Handler 기능·Trial/Paid·재시작·자연 Lease 만료와 RC2.5 업그레이드를 검증했습니다. 최종 ZIP clean-room 및 전체 부하 Gate는 별도 최종 보고를 확인합니다.

Windows Nginx named pipe 비밀번호 공급은 검증되지 않았습니다. 격리 시험은 전용 ACL의 임시 시험 비밀번호 파일을 Nginx 시작 직후 삭제했고 운영 키는 사용하지 않았습니다. 운영 secret 공급은 고객 환경에 맞게 보호합니다. 기능시험이나 fuzz 수치로 최고 RPS, 무제한 동시접속, SLA, 장기 memory leak 부재, 128KiB/1MiB payload 지원을 주장하지 않습니다.

신규 Paid 등록과 기존 Unit 장치 이전

Trial을 사용하지 않는 새 Paid 장치는 identity를 한 번 생성한 뒤 register를 실행합니다. 기존 Trial을 Paid로 전환할 때만 paid를 사용하며 같은 장치 identity와 Trial 기록을 유지합니다. Trial 장치 이전은 지원하지 않습니다.

새 서버에서 register를 실행하고 표시된 Device Code를 https://pqc.odreai.com/payment/register/?flow=activate 에 입력합니다. 웹에서 License ID와 License Key를 검증한 뒤 새 Unit 사용 또는 기존 Unit 이전을 직접 선택합니다. 고객 회원가입이나 로그인은 없습니다. License Key를 명령행, 지원 메시지 또는 기존 장치 요청 파일에 넣지 않습니다.

기존 Unit 이전은 대상 installation과 정상 교체 또는 기존 장치 접근불가를 선택합니다. 새 장치 등록만으로 Unit을 이전하지 않습니다. 정상 교체는 기존 장치가 transfer-release를 지원하는 승인된 버전이어야 합니다. 이전 버전은 identity를 보존하는 승인된 업그레이드부터 수행합니다.

정상 교체: 기존 장치의 신규 업무 트래픽을 막되 Native는 실행 상태로 유지합니다. 웹에서 기존 장치 이전 요청 JSON을 받은 뒤 기존 장치에서 아래 transfer-release를 실행합니다. Native는 admission 종료, 처리 중 요청 drain, 보호 상태 기록 후 서버에 장치 서명 proof를 보냅니다. 완료 후 기존 장치를 다시 시작하지 않습니다.

고장 교체는 지원 승인이 필요합니다. 정상 교체 중 Native가 중단되면 같은 웹 작업에서 접근불가 확인란과 복구 요청을 선택합니다. 새 Native가 같은 복구 요청에 동의하고 지원 담당자가 승인합니다. 원래 선택·Unit을 바꾸거나 drain 성공을 가정하지 않습니다. 두 경우 모두 기존 Offline Lease가 모두 만료될 때까지 새 보호 실행 권한을 발급하지 않습니다.

register는 같은 state-directory로 다시 실행해 계속합니다. 서버 commit 뒤 응답 유실·디스크 오류가 발생해도 같은 요청 결과를 복구하고 서명·새 장치 결속 검증 후 원자 저장합니다. 새 Unit이나 Trial을 재등록하지 않고, 과거 state를 복원하거나 기존 private key·DPAPI·Gateway identity를 새 장치로 복사하지 않습니다. 새 장치는 자신의 키와 Gateway identity를 사용합니다.

LICENSE_UNIT_LIMIT은 이전 또는 추가 구매가 필요하다는 뜻입니다. SUPPORT_PENDING은 승인 대기, WAITING_OLD_LEASE는 만료 대기입니다. COMMITTED는 서버 확정이며 APPLIED는 Native 로컬 저장 확인입니다. 둘 다 업무 통합 완료의 증거는 아닙니다. status, Gateway→Core→Handler 요청과 재시작을 확인한 뒤 트래픽을 엽니다.

Windows Server 2022

& .\runtime\python.exe .\odre-native.py register `
  --state-directory $state `
  --trust-config $trust --trust-pin $trustPin

Ubuntu 24.04

python3.12 ./odre-native-ubuntu.py register \
  --state-directory "$state" \
  --trust-config "$trust" --trust-pin "$trust_pin"
