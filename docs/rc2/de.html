RC2-Installation und Native-Befehle

Zuerst Kunden-ZIP und unabhängig freigegebenes Verifier-Kit prüfen. In ein neues geschütztes unveränderliches Verzeichnis installieren und die RC2-Native-Anleitung befolgen.

Windows: Im freigegebenen Bereitstellungskontext .\install-odre-pqc.ps1 -InstallDirectory <NEW_ABSOLUTE_DIRECTORY> aus der verifizierten Auslieferung ausführen.

Linux: ./install-odre-pqc.sh im freigegebenen Bereitstellungskontext ausführen. Vertrauenswürdiges Python 3.12, OpenSSL 3.5.8 und freigegebene Voraussetzungen sind erforderlich. Das Zielverzeichnis muss neu sein.

ODRE_TRUSTED_PYTHON
ODRE_TRUSTED_PYTHON_SHA256
ODRE_INSTALL_PREREQUISITES
ODRE_INSTALL_PREREQUISITES_SHA256
ODRE_INSTALL_DIRECTORY

Installation, Aktivierung und Laufzeitprüfung

Windows: WINDOWS_SERVER_2022\runtime\python.exe + WINDOWS_SERVER_2022\odre-core-cli.py / odre-native.py
Linux: LINUX_FAMILY/runtime/bin/python3.12 + LINUX_FAMILY/odre-core-cli.py / odre-native-ubuntu.py

# Windows — installed WINDOWS_SERVER_2022 directory
& .\runtime\python.exe -B .\odre-core-cli.py doctor --state-directory <STATE_DIRECTORY>
# Linux — installed LINUX_FAMILY directory
./runtime/bin/python3.12 -B ./odre-core-cli.py doctor --state-directory <STATE_DIRECTORY>

init — init erstellt die Native-Geräteidentität und wird nur bei einer neuen Installation verwendet.

doctor — doctor prüft die signierte Laufzeit ohne Aktivierung.

verify — verify prüft Core nach bestehender Lease-Zulassung. Den tatsächlichen Gateway → Core → Protected Handler-Pfad separat prüfen.

status — status liest den Native-Zustand. Trial und Paid werden mit dem installierten Native-Launcher und der freigegebenen lokalen Trust-Konfiguration aktiviert.

--state-directory · --trust-config · --trust-pin

Trial und Paid verwenden dasselbe ODRE PQC 0.3.1 / RC2 ZIP. Ein Download startet weder Trial noch Zahlung.

Bestehende Identity, License, Unit, Lease und Gerätezustände bewahren. Bestehende Installationen nicht neu initialisieren und privates Material nicht auf andere Geräte kopieren.

Signierte lokale Updates

Der konfigurierte Kunden-Updater prüft freigegebene lokale Eingaben alle 15 Sekunden. Nach Signatur-, Integritäts- und Kompatibilitätsprüfung übergibt er sie an die lokale AUM. Dieses Release lädt keine neuen Versionen von einem zentralen Update Server herunter.
