Quick start

Install and verify the official bundle, connect the server integration, activate, then test the running path. Existing Android, iOS and Web clients need no code changes or SDK replacement. Follow the release-specific guide for exact installer and Gateway API names.

  1. Verify and install the official bundle; check dependencies.
  2. New installation only: odre-pqc init.
  3. Run odre-pqc doctor.
  4. Run odre-pqc verify (independent Core self-test).
  5. In main.py, register Core with install(app), then connect Gateway and the Commercial gate; configure identity, trust and protected routes.
  6. Complete Trial activation or, for a paid license, odre-pqc-commercial activate and web approval.
  7. Check odre-pqc-commercial status; for paid activation confirm ACTIVE, LEASE_VALID, integrity PASS and Unit allocation.
  8. Start the customer server and Gateway private Core.
  9. Run odre-pqc status against the intended running Core.
  10. Smoke-test Gateway → Core → Protected Handler, including fail-closed behavior; do not confuse this with Core self-tests.
  11. Open Production traffic only after all applicable gates pass.
Verify Release Manifest signature → artifact SHA-256 → install only after PASS. The published v0.2.9 Core wheel hash is a Core reference, not the hash of the final Commercial + Gateway + Core bundle.

Verify the official bundle's Release Manifest signature and artifact SHA-256 before installation, then check dependencies. Use the supplied Commercial + Gateway + Core bundle and its installation guide.

  1. Confirm Windows Server 2022 AMD64 or Ubuntu 24.04 LTS AMD64 and CPython 3.12.
  2. Verify the official bundle's Release Manifest signature and artifact SHA-256 before installation, then check dependencies. Use the supplied Commercial + Gateway + Core bundle and its installation guide.
  3. Verify Release Manifest signature → artifact SHA-256 → install only after PASS. The published v0.2.9 Core wheel hash is a Core reference, not the hash of the final Commercial + Gateway + Core bundle.
  4. Run odre-pqc init once for a new installation only. Preserve existing configuration, keys and state during updates or reinstalls. Before server startup, run odre-pqc doctor and then odre-pqc verify. Verify is an independent Core self-test, not a test of your Gateway integration.
  5. Import ODRE PQC, register the Core boundary with install(app), then connect Gateway and the Commercial gate in main.py. Production integration

The confirmed Core registration entry point is intentionally small:

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)
This registers the Core boundary only. Production use also requires the customer bundle's Gateway and Commercial gate, identity, keys, trust, protected-route, startup, and shutdown configuration.

odre-pqc verify is an independent Core self-test. It does not prove the running Gateway → Core → Protected Handler path; perform the release-specific smoke test before opening protected traffic.

Operations

A normal shutdown stops new protected admission, drains bounded in-flight work, disposes sessions and leases, closes native resources, releases locks, and records stopped state. Crash recovery re-checks ownership, stale locks, sessions, and partially initialized runtime before returning to Ready.

Doctor

Diagnoses the operating system, architecture, Python runtime, file and parent permissions, hashes, symbols, providers, dependencies, and access to local state. Treat an unresolved condition as a deployment blocker for protected traffic.

Verify

odre-pqc verify runs independent Core cryptographic self-tests with temporary keys and a temporary DB, including ML-KEM-768 and ML-DSA-65. Run it during installation; do not treat it as customer FastAPI/Gateway integration evidence or repeat it for that purpose.

Status

odre-pqc status queries authenticated runtime evidence from a running Core, not a verify result file. Run it after startup. Core status success does not by itself verify Gateway private Core or Gateway → Core → Handler integration; those require a separate smoke test.

Troubleshooting

  • Hash mismatch: stop installation and obtain the artifact again through the official delivery route.
  • Unsupported OS, architecture, or Python version: do not describe the environment as verified; contact technical support before deployment.
  • Doctor or verify failure: keep protected traffic disabled until the reported condition is resolved.
  • Missing license email: do not purchase again; use the recovery page or license support.
  • Operational instructions not covered publicly: use the customer guide supplied with the release.
