01

A protection boundary inside the application.

Existing clients → HTTPS/TLS → FastAPI → Gateway → ODRE v3 → Core → Protected Handler. Clients keep their API contract; ODRE v3 runs between Gateway and Core, not between mobile devices and the server.

Existing FastAPI path
Client→HTTPS/TLS→FastAPI Handler
Path with ODRE PQC
Client→HTTPS/TLS→Gateway→ODRE v3→private Core→Protected Handler
  • Client code and the HTTPS/API contract remain unchanged.
  • PQC is enforced between Gateway and the private Core inside the server.
  • If verification fails, the Protected Handler does not execute.
  • No plaintext or classical fallback is used for a protected request.

The protection boundary is inside the server. This is not mobile-to-server end-to-end PQC.

04

A defined path from installation to operation.

  • 01 · InstallVerify the official bundle's Release Manifest signature and artifact SHA-256 before installation, then check dependencies. Use the supplied Commercial + Gateway + Core bundle and its installation guide.
  • 02 · InitializeRun odre-pqc init once for a new installation only. Preserve existing configuration, keys and state during updates or reinstalls.
  • 03 · DiagnoseBefore server startup, run odre-pqc doctor and then odre-pqc verify. Verify is an independent Core self-test, not a test of your Gateway integration.
  • 04 · IntegrateImport ODRE PQC, register the Core boundary with install(app), then connect Gateway and the Commercial gate in main.py. Configure Gateway identity, keys, trust, protected routes and startup/shutdown; Core registration alone is not the complete integration.
  • 05 · OperateComplete the applicable Trial or paid activation procedure and check Commercial status. Start the server and private Core, check running Core status, then smoke-test Gateway → Core → Handler before opening traffic.
