Native Bundle quick start

Use the verified Native Bundle for your operating system. Its commands and state are separate from the legacy Wheel client.

  1. Verify the official delivery with the independent verifier and follow the included installation guide.
  2. For an existing installation, preserve its identity and state; check status before continuing.
  3. For a new Paid device, use register and the Native portal. Convert an existing Native Trial with paid on that same installation.
  4. Confirm the valid signed Lease and test Gateway → Core → Protected Handler before opening production traffic.

Existing Wheel installation guide

Wheel의 odre-pqc-commercial activate/deactivate는 Native 고객 명령이 아닙니다. Wheel 상태로 Native를 활성화하거나 이전하지 마세요. 장치 교체·서버 이전은 현재 지원 검토와 승인이 필요합니다. 배포된 Native launcher에는 고객 직접 이전 기능이 없습니다. 새 장치 등록만으로 기존 Unit이 이전되지 않습니다. 기존 Unit 이전과 여유 Unit 추가 할당 중 하나를 지원 담당자와 명시적으로 선택하세요. Trial 재등록으로 이전을 대신하지 마세요.

  1. 공식 bundle 무결성 검증·설치 및 의존성 확인.
  2. 신규 설치에서만 odre-pqc init.
  3. odre-pqc doctor 실행.
  4. odre-pqc verify 실행 (독립 Core 자체시험).
  5. main.py에서 install(app)으로 Core 등록 후 Gateway와 Commercial gate 연결. identity·trust·보호 route 설정.
  6. Trial 활성화 또는 유료 라이선스의 odre-pqc-commercial activate + 웹 승인 완료.
  7. odre-pqc-commercial status 확인. 유료 활성화는 ACTIVE·LEASE_VALID·integrity PASS·Unit 할당 확인.
  8. 고객 서버와 Gateway private Core 시작.
  9. 대상 실행 중 Core에 odre-pqc status 실행.
  10. Gateway → Core → Protected Handler 실제 Smoke Test 및 fail-closed 검증. Core 자체시험과 구분.
  11. 해당 Gate가 모두 PASS일 때만 Production 트래픽 개방.
Release Manifest 서명 → artifact SHA-256 순서로 확인하고 PASS 후에만 설치합니다. 공개된 v0.2.9 Core Wheel 해시는 Core reference이며 최종 Commercial + Gateway + Core bundle 해시가 아닙니다.

설치

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

설치 전에 공식 bundle의 Release Manifest 서명과 artifact SHA-256을 검증하고 의존성을 확인합니다. 제공된 Commercial + Gateway + Core bundle과 해당 설치 가이드를 사용합니다.

  1. Windows Server 2022 AMD64 또는 Ubuntu 24.04 LTS AMD64와 CPython 3.12를 확인합니다.
  2. 설치 전에 공식 bundle의 Release Manifest 서명과 artifact SHA-256을 검증하고 의존성을 확인합니다. 제공된 Commercial + Gateway + Core bundle과 해당 설치 가이드를 사용합니다.
  3. Release Manifest 서명 → artifact SHA-256 순서로 확인하고 PASS 후에만 설치합니다. 공개된 v0.2.9 Core Wheel 해시는 Core reference이며 최종 Commercial + Gateway + Core bundle 해시가 아닙니다.
  4. odre-pqc init은 신규 설치에서만 1회 실행합니다. 업데이트·재설치에서는 기존 설정·키·state를 보존합니다. 서버 시작 전에 odre-pqc doctor, odre-pqc verify 순서로 실행합니다. verify는 독립 Core 자체시험이며 고객 Gateway 통합 검증이 아닙니다.
  5. ODRE PQC를 import하고 install(app)으로 Core 경계를 등록한 뒤, main.py에 Gateway와 Commercial gate를 연결합니다. Gateway identity·key·trust·보호 route·startup/shutdown 설정이 필요하며 Core 등록만으로 통합이 완료되지는 않습니다. 해당 Trial 또는 유료 활성화 절차를 완료하고 Commercial status를 확인합니다. 서버와 private Core를 시작한 뒤 실행 중 Core status와 Gateway → Core → Handler Smoke Test를 확인하고 트래픽을 개방합니다.

Production 통합

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

확인된 Core 등록 진입점은 의도적으로 작습니다.

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)
이 코드는 Core 경계만 등록합니다. Production 사용에는 고객 bundle의 Gateway와 Commercial gate, identity, key, trust, 보호 route, startup 및 shutdown 설정이 추가로 필요합니다.

odre-pqc verify는 독립 Core 자체시험입니다. 실행 중인 Gateway → Core → Protected Handler 경로를 증명하지 않으므로 보호 트래픽을 열기 전에 릴리스별 Smoke Test를 수행해야 합니다.

라이선스 전달

정상적인 Paddle 구매에서는 결제창에 입력한 이메일을 서명된 결제 절차로 다시 확인한 후 라이선스 전달에 사용합니다. 브라우저 복귀 페이지만 결제 증명으로 취급하지 않습니다.

발급 이메일의 License ID와 License Key는 보안 활성화 페이지에서 서버 검증할 수 있습니다. 장치 귀속과 Offline Lease 발급은 설치된 ODRE PQC에서 완료합니다.

Status

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc status는 verify 결과 파일이 아니라 실제 실행 중 Core의 인증된 runtime evidence를 조회합니다. 서버 시작 후 실행하세요. Core status 성공만으로 Gateway private Core 또는 Gateway → Core → Handler 통합을 검증한 것은 아니며 별도 Smoke Test가 필요합니다.

Verify

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc verify는 임시 키·임시 DB로 ML-KEM-768·ML-DSA-65 등을 검사하는 독립 Core 암호 자체시험입니다. 설치 단계에서 실행하며 고객 FastAPI/Gateway 통합 증거로 간주하거나 그 목적으로 다시 실행하지 않습니다.

운영

정상 종료는 새 보호 요청 수락을 중단하고 진행 중 작업을 제한 시간 안에 마친 뒤 session과 lease를 폐기하고 native resource와 lock을 해제합니다. Crash 복구는 Ready로 돌아가기 전에 소유권, 오래된 lock·session과 부분 초기화 상태를 다시 확인합니다.

업데이트

검증된 업데이트는 지원되는 업데이트 경로로 적용합니다. 안전하게 완료할 수 없으면 활성 버전을 전환하지 않습니다.

문제 해결

Doctor

운영체제, 아키텍처, Python runtime, 파일·상위 경로 권한, hash, symbol, provider, dependency와 로컬 상태 접근을 진단합니다. 해결되지 않은 조건은 보호 트래픽 배포 차단 사유로 취급하세요.

문제 해결

  • Hash 불일치: 설치를 중단하고 공식 전달 경로에서 파일을 다시 받으세요.
  • 지원되지 않는 OS·아키텍처·Python: 검증 환경으로 표시하지 말고 배포 전 기술 지원에 문의하세요.
  • Doctor 또는 verify 실패: 해당 조건을 해결할 때까지 보호 트래픽을 비활성화하세요.
  • 라이선스 이메일 누락: 다시 구매하지 말고 복구 페이지 또는 라이선스 지원을 이용하세요.
  • 공개 범위 밖 운영 절차: 릴리스와 함께 제공된 고객 가이드를 따르세요.
