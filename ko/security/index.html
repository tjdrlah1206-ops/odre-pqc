보호 요청이 실행되는 조건.

Runtime, 세션, 순서, 재전송, 요청 검증을 통과해야 보호 Handler가 실행됩니다.

릴리스 및 검증보안 문서
01

보안 아키텍처

ML-KEM-768과 ML-DSA-65는 서버 내부 경계에서 동작합니다. 검증할 수 없는 보호 요청은 차단됩니다.

  • Admission메시지 형식, 필수 필드, 인코딩, 전체 크기와 지원 응답 형식을 확인합니다.
  • 핸드셰이크와 세션프로토콜 버전, 알고리즘 세트, 양측 자료, transcript, 경로 의미와 세션 식별자를 결합합니다.
  • 순서와 재전송정확히 다음 순서만 허용하고 중복·rollback·gap·동시 중복 실행을 거부합니다.
  • 요청 의미 바인딩method, 정규화 경로·query, 보안 관련 header, payload, session, sequence, protocol과 message type을 결합합니다.
  • 응답 바인딩지원되는 status, content type, 선택 header, cookie, response body와 요청 관계를 보호합니다.
02

암호 기술의 역할

ML-KEM-768

프로토콜에서 사용할 공유 비밀 재료를 캡슐화하고 복구합니다.

ML-DSA-65

핸드셰이크 자료와 transcript 무결성을 인증합니다.

하이브리드 핸드셰이크

필수 암호 구성요소를 같은 peer, session, route 의미에 결합합니다.

암호 프리미티브 호출 성공만으로 보호가 성립하지 않습니다. 런타임 식별, transcript 바인딩, 키 확인과 세션 생성도 완료되어야 합니다.
03

조용한 classical-only downgrade 없이 차단합니다.

런타임 식별, provider·dependency 신뢰, PQC self-test, handshake transcript, 활성 session, 엄격한 sequence, 의미 결합, worker 소유권 또는 안전한 복구를 확인할 수 없으면 보호 경로는 핸들러에 진입하지 않습니다.

애플리케이션 정책에 따라 공개 경로는 계속 제공할 수 있습니다. 보호 런타임을 사용할 수 없다는 이유로 보호 통제를 우회하지 않으면서 명시적 공개 health 경로를 유지할 수 있습니다.

위협 경계와 한계

표면대표 조건통제 위치
Admission잘못되거나 과도한 입력, smuggling 형태Admission gate
Session만료 또는 다른 세션 재사용Session engine
Sequence중복, rollback, gap 또는 raceAtomic sequence gate
네이티브 파일TOCTOU, symlink, junction, reparse, dependency injection플랫폼 어댑터와 런타임 신뢰
Lifecycle오래된 lease, crash, 이른 shutdownLifecycle controller
클라이언트 → 서버는 기존 HTTPS/TLS이며 mobile-to-server E2E PQC가 아닙니다. WAF·호스트 보안·업무 권한·TLS를 대체하지 않으며 root/OS 완전 탈취 이후의 보호까지 보장하지 않습니다.

릴리스 및 검증

Security는 보호 통제를 설명하고 Trust는 현재 산출물과 검증자료를 보관합니다.

산출물 식별정보, 지원 플랫폼, 해시, 검증 결과와 유지보수 상태는 Trust에서 확인합니다.
