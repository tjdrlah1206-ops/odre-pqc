Native Bundle quick start

Use the verified Native Bundle for your operating system. Its commands and state are separate from the legacy Wheel client.

  1. Verify the official delivery with the independent verifier and follow the included installation guide.
  2. For an existing installation, preserve its identity and state; check status before continuing.
  3. For a new Paid device, use register and the Native portal. Convert an existing Native Trial with paid on that same installation.
  4. Confirm the valid signed Lease and test Gateway → Core → Protected Handler before opening production traffic.

Existing Wheel installation guide

Wheelのodre-pqc-commercial activate/deactivateはNative向けコマンドではありません。Wheelの状態をNativeへ移さないでください。 端末交換・サーバー移行には現在サポートの審査と承認が必要です。公開launcherにセルフサービス移行機能はありません。新規登録だけでは既存Unitは移転しません。既存Unit移転と空きUnit追加割当を明示的に選択し、Trial再登録で代用しないでください。

  1. 公式bundleの完全性を検証してインストールし、依存関係を確認。
  2. 新規インストール時のみodre-pqc init。
  3. odre-pqc doctorを実行。
  4. odre-pqc verifyを実行（独立したCore自己試験）。
  5. main.pyでinstall(app)によるCore登録後、GatewayとCommercial gateを接続。identity、trust、保護routeを設定。
  6. Trial有効化、または有料ライセンスのodre-pqc-commercial activateとWeb承認を完了。
  7. odre-pqc-commercial statusを確認。有料有効化ではACTIVE、LEASE_VALID、integrity PASS、Unit割当を確認。
  8. 顧客サーバーとGateway private Coreを起動。
  9. 対象の稼働中Coreに対してodre-pqc statusを実行。
  10. Gateway → Core → Protected Handlerの実経路とfail-closedをスモークテスト。Core自己試験とは区別。
  11. 該当するすべてのGateがPASSの場合のみProductionトラフィックを開放。
Release Manifestの署名 → artifactのSHA-256を確認し、PASS後にのみインストールします。公開v0.2.9 Core WheelのハッシュはCoreの参照値であり、最終Commercial + Gateway + Core bundleのハッシュではありません。

Verification & known limitation

インストール

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

インストール前に公式bundleのRelease Manifest署名とartifactのSHA-256を検証し、依存関係を確認します。提供されたCommercial + Gateway + Core bundleと対応する導入ガイドを使用してください。

  1. Windows Server 2022 AMD64またはUbuntu 24.04 LTS AMD64とCPython 3.12であることを確認します。
  2. インストール前に公式bundleのRelease Manifest署名とartifactのSHA-256を検証し、依存関係を確認します。提供されたCommercial + Gateway + Core bundleと対応する導入ガイドを使用してください。
  3. Release Manifestの署名 → artifactのSHA-256を確認し、PASS後にのみインストールします。公開v0.2.9 Core WheelのハッシュはCoreの参照値であり、最終Commercial + Gateway + Core bundleのハッシュではありません。
  4. odre-pqc initは新規インストール時のみ1回実行します。更新や再インストールでは既存の設定、鍵、stateを保持してください。 サーバー起動前にodre-pqc doctor、odre-pqc verifyの順に実行します。verifyは独立したCore自己試験であり、顧客のGateway統合試験ではありません。
  5. ODRE PQCをimportし、install(app)でCore境界を登録した後、main.pyにGatewayとCommercial gateを接続します。Gatewayのidentity、key、trust、保護route、startup/shutdownを設定します。Core登録だけでは統合は完了しません。 該当するTrialまたは有料ライセンスの有効化を完了し、Commercial statusを確認します。サーバーとprivate Coreを起動し、稼働中CoreのstatusとGateway → Core → Handlerのスモークテストを確認してからトラフィックを開放します。

Production統合

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

確認済みのCore登録エントリーポイントは意図的に小さく設計されています。

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)
このコードはCore境界のみを登録します。Production利用には、顧客bundleのGatewayとCommercial gate、identity、key、trust、保護route、startup、shutdownの設定が別途必要です。

odre-pqc verifyは独立したCore自己試験です。稼働中のGateway → Core → Protected Handler経路を証明するものではないため、保護トラフィックを開く前にリリース固有のSmoke Testを実施してください。

運用・アップデート

Status

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc statusはverifyの結果ファイルではなく、稼働中Coreの認証済みruntime evidenceを照会します。サーバー起動後に実行してください。Core status成功だけではGateway private CoreやGateway → Core → Handlerの統合確認にはなりません。別途スモークテストが必要です。

Verify

The commands in this section apply to existing Wheel installations. For Native Bundle, follow the dedicated installation guide. View Native guide

odre-pqc verifyは一時鍵と一時DBを使い、ML-KEM-768、ML-DSA-65などを検証する独立したCore暗号自己試験です。導入時に実行します。顧客FastAPI/Gateway統合の証拠とはせず、その目的で再実行しないでください。

運用

通常停止では、新規保護リクエストの受付を止め、処理中作業を上限内で完了し、セッションとleaseを破棄し、ネイティブ資源とlockを解放して停止状態を記録します。crash復旧では、Readyへ戻る前に所有権、古いlock、セッション、不完全なランタイム初期化を再確認します。

アップデート

検証済みアップデートは対応する更新経路で適用します。安全に完了できない場合、稼働中の版は切り替えません。

問題解決

Doctor

OS、アーキテクチャ、Pythonランタイム、ファイルと親ディレクトリの権限、hash、symbol、provider、依存関係、ローカル状態へのアクセスを診断します。未解決条件は保護トラフィックの導入阻害要因として扱います。

トラブルシューティング

  • Hash不一致: インストールを中止し、公式提供経路からartifactを再取得してください。
  • 未対応のOS、アーキテクチャ、Python版: 検証済み環境と表示せず、導入前に技術サポートへ連絡してください。
  • doctorまたはverify失敗: 報告された条件を解決するまで保護トラフィックを無効のままにしてください。
  • ライセンスメール未着: 再購入せず、復旧ページまたはライセンスサポートを利用してください。
  • 公開範囲外の運用手順: リリースと共に提供された顧客ガイドを参照してください。
