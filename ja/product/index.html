ODRE PQC製品

FastAPI向け耐量子保護。

ODRE PQCはサーバー内部で保護リクエストを検証してからFastAPI Handlerを実行します。

01

ODRE PQCとは

ODRE PQCは汎用暗号ツールキットではありません。ランタイム識別、ポスト量子ハンドシェイク、セッション状態、厳密なシーケンス処理、リプレイ防止、リクエストの意味、保護された応答、ライフサイクル制御を一つのFastAPI実行境界にまとめます。

ポスト量子アルゴリズムを呼び出すだけでは、検証済みランタイムが読み込まれたか、リプレイで業務ハンドラーが二重実行されないかは判断できません。境界はこれらを保護対象コードの実行前に確認します。

02

統合方法

既存クライアント → HTTPS/TLS → FastAPI → Gateway → ODRE v3 → Core → Protected Handler。クライアントのAPI契約は維持します。ODRE v3が動作する区間はモバイル端末とサーバー間ではなく、GatewayとCore間です。

Existing clientHTTPS / FastAPIGateway / ODRE v3Private CoreProtected Handler

プラットフォーム用インストーラーで製品を導入します。FastAPIでODRE PQCをimportし、install(app)を呼び出します。Core、Native、Gateway、license/lease、session/replay、Fail-Closed、update lifecycleはODRE内部で管理します。

標準FastAPIアプリケーション統合

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)

これは顧客向けの標準アプリケーション統合です。製品インストールは別のプラットフォーム手順であり、ODREが内部のCore、Native、Gateway、Commercial gate統合を管理します。

顧客はFastAPIアプリケーション、保護routeとHandler、アプリケーションの認証・認可、business logicとDB、実際の保護リクエスト検証、Production承認を担当します。ODREは内部のセキュリティ境界とlifecycleを管理します。
03

保護ルートと公開ルート

保護ルート

保護ルートは必要なセキュリティ契約を満たした場合だけ実行されます。不正なエンベロープ、無効なセッション、重複または欠落シーケンス、意味の不一致、信頼できないランタイム状態ではハンドラーに入りません。

公開ルート

保護ルートが遮断されても、アプリケーション方針に従って公開healthや情報ルートを提供できます。Fail-closedはすべての公開ルートの停止を意味しません。

04

導入と運用モデル

  • Install公式artifactのRelease Manifest署名とSHA-256を確認し、Windowsでは .\install-odre-pqc.ps1、Linuxでは sudo ./install-odre-pqc.sh で製品をインストールします。
  • initodre-pqc initは新規インストール時のみ1回実行します。更新や再インストールでは既存の設定、鍵、stateを保持してください。
  • doctorプラットフォーム、権限、ハッシュ、シンボル、依存関係、状態ストアへのアクセスを診断します。
  • verifyodre-pqc verifyは一時鍵と一時DBを使い、ML-KEM-768、ML-DSA-65などを検証する独立したCore暗号自己試験です。導入時に実行します。顧客FastAPI/Gateway統合の証拠とはせず、その目的で再実行しないでください。
  • FastAPI統合製品のインストール後、ODRE PQCをimportしてinstall(app)を適用します。保護routeとHandler、アプリケーションの認証・認可を構成します。ODRE内部のCore、Native、Gateway、lifecycleの接続は製品が管理します。
  • status該当するTrialまたは有料ライセンスの有効化を完了し、製品statusを確認します。顧客アプリケーションで実際の保護リクエストと期待されるHandler・DB動作を検証し、Production承認後にトラフィックを開放します。
