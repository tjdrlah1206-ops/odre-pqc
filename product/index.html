01

What ODRE PQC is

ODRE PQC is not a general-purpose cryptography toolkit. It composes runtime identity, a post-quantum handshake, session state, strict sequence handling, replay defense, request semantics, protected responses, and lifecycle controls into one FastAPI execution boundary.

Calling a post-quantum algorithm does not by itself determine whether the verified runtime was loaded or whether a replay can execute a business handler twice. The boundary turns those questions into conditions checked before protected code runs.

02

How it integrates

Existing clients → HTTPS/TLS → FastAPI → Gateway → ODRE v3 → Core → Protected Handler. Clients keep their API contract; ODRE v3 runs between Gateway and Core, not between mobile devices and the server.

Import ODRE PQC, register the Core boundary with install(app), then connect Gateway and the Commercial gate in main.py. Configure Gateway identity, keys, trust, protected routes and startup/shutdown; Core registration alone is not the complete integration.

Confirmed Core registration entry point

from fastapi import FastAPI
from odre_pqc import install

app = FastAPI()
install(app)

This registers the Core boundary only. Production use also requires the customer bundle's Gateway and Commercial gate, identity, keys, trust, protected-route, and lifecycle configuration.

Keep existing client code, HTTPS APIs, handlers and DB semantics. The application still owns business authorization, input validation and public-route policy. Only configured protected routes pass through the Gateway/Core boundary.
03

Protected and public routes

Protected routes

A protected route executes only after the required security contract is satisfied. A malformed envelope, invalid session, duplicate or skipped sequence, semantic mismatch, or untrusted runtime state blocks handler entry.

Public routes

Public health or information routes may remain available according to application policy when protected routes are blocked. Fail-closed protection does not require every public route to stop.

Deployment and operational model

  • InstallVerify the official bundle's Release Manifest signature and artifact SHA-256 before installation, then check dependencies. Use the supplied Commercial + Gateway + Core bundle and its installation guide.
  • initRun odre-pqc init once for a new installation only. Preserve existing configuration, keys and state during updates or reinstalls.
  • doctorDiagnose platform, permissions, hashes, symbols, dependencies, and state-store access.
  • verifyodre-pqc verify runs independent Core cryptographic self-tests with temporary keys and a temporary DB, including ML-KEM-768 and ML-DSA-65. Run it during installation; do not treat it as customer FastAPI/Gateway integration evidence or repeat it for that purpose.
  • Gateway / CoreImport ODRE PQC, register the Core boundary with install(app), then connect Gateway and the Commercial gate in main.py. Configure Gateway identity, keys, trust, protected routes and startup/shutdown; Core registration alone is not the complete integration.
  • statusComplete the applicable Trial or paid activation procedure and check Commercial status. Start the server and private Core, check running Core status, then smoke-test Gateway → Core → Handler before opening traffic.
