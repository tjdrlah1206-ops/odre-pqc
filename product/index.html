Product

What you're actually installing.

ODRE PQC is a commercial, self-hosted, application-level security boundary for FastAPI applications. It is installed on your own servers as a single package and enforces post-quantum cryptography — ML-KEM-768 (FIPS 203) and ML-DSA-65 (FIPS 204) — directly in the request and session protocol, at the application security boundary. ODRE PQC does not replace TLS/HTTPS or claim that TLS itself uses PQC. It is available on a self-service basis: no account, no login, and no sales contact required to purchase or run it.

architecture

Where the boundary sits

ODRE PQC sits between your FastAPI application and its protected handlers: HTTPS → FastAPI → Security Boundary → Protected Handler. Public routes can be left outside the boundary; protected routes pass through it on every request.

fail-closed

Fail-Closed

When a request fails verification, the protected handler does not execute. There is no fallback path into application code for an unverified request. This is enforced at the boundary itself, not left to individual handler logic.

Fail-closed governs whether the protected handler runs for an unverified request. It does not extend to protection against every application bug or service outage.
replay & sequence

Replay and Sequence Defense

Protected sessions are stateful. Each request is checked against session state to reject resent requests and out-of-order sequences before they reach your handler, rather than relying on application-level idempotency checks alone.

request / response

Request/Response Binding

Requests and their responses are cryptographically bound to the session they belong to, so a response cannot be replayed or substituted into a different session context.

runtime integrity

Runtime Integrity

ODRE PQC verifies its own runtime artifacts against a signed manifest to detect tampering of the product itself.

This covers the ODRE PQC runtime and its artifacts. It does not extend to the integrity of the underlying operating system, kernel, or hypervisor.
data plane / lease

Local Data Plane / Offline Lease

Protected request and response traffic stays within your own infrastructure — it is not routed through ODRE servers to be enforced. Licensing is verified locally through a signed, device-bound offline lease, so enforcement continues without a live, continuous connection to a vendor control plane.

The offline lease is valid for a bounded period. See the Trust page for what happens as that period runs out and what the vendor control plane is responsible for.
automatic update

Automatic Update Module

Included at every tier. Each update is signature-verified, staged, and self-tested before going live. The switch to the new version is atomic and preceded by a traffic drain; health is verified after the switch, and a failed health check triggers automatic rollback to the last known-good state — including recovery after a process termination or a reboot.

Known-good and rollback refer to ODRE PQC's own last verified version and configuration — not to your application's data, database, or infrastructure.
lifecycle

Lifecycle

Install, update, uninstall, and reinstall are handled as part of the same product — not as separate tooling you assemble yourself. Device-bound licensing carries through reinstall and device transfer within the terms of your lease.

authentication

Where this stops

ODRE PQC does not replace application-level authentication (e.g. JWT, OAuth) or authorization (e.g. RBAC). It operates independently of, and in addition to, your application's identity and access control layer.

platforms
